<h1><a id="_pgr6lsol61bk"></a><strong>Product Requirements Document (PRD): Project "ServiceSync" (Challenge 2)</strong></h1><h2><a id="_h0ij0q875td1"></a><strong>1. Executive Summary</strong></h2><p>This project is an Agentic AI System designed to automate the end-to-end lifecycle of informal service requests (plumbers, AC technicians, IT support). Operating under a "One App, Two Worlds" architecture, the system provides a sleek user interface for clients while utilizing a Google Antigravity-powered agent to handle intent parsing, real-world discovery via Google Maps, and simulated booking execution.</p><h2><a id="_8vawmh7bk99u"></a><strong>2. Technical Stack &amp; Task Distribution</strong></h2><p>To ensure delivery within the 5-day sprint, the architecture is strictly decoupled.</p><ul><li><strong>Frontend (User App):</strong> Flutter. to ensure cross-platform compatibility and fluid UI state management.</li><li><strong>Core Orchestrator:</strong> Google Antigravity. This is your domain. It will act as the "brain" handling the logic pipeline.</li><li><strong>External Data Source:</strong> Google Maps Places API (for real-world provider discovery).</li><li><strong>Simulation Backend:</strong> Firebase Firestore (a lightweight NoSQL database to act as the "Mock Seller App" and trigger UI updates).</li></ul><h2><a id="_mvyjb489v2wo"></a><strong>3. The End-to-End User Flow</strong></h2><p>This is exactly what the user will experience, step-by-step, from opening the app to getting a booking confirmation.</p><h3><a id="_e7ltsvws0q6a"></a><strong>Step 1: Natural Language Input</strong></h3><ul><li><strong>Action:</strong> The user opens the Flutter app and types or speaks a request in Roman Urdu, Urdu, or English .</li><li><strong>Example:</strong> "Mujhe G-13 mein kal subah AC technician chahiye".</li><li><strong>UI Component:</strong> A chat-like interface or a single dynamic search bar.</li></ul><h3><a id="_ewn49ogvzr62"></a><strong>Step 2: Agentic Triage (Antigravity)</strong></h3><ul><li><strong>Action:</strong> The Flutter app sends the raw text string to the Antigravity agent.</li><li><strong>Process:</strong> The agent processes the input and extracts three key variables:<ul><li>Service Category (e.g., AC Repair).</li><li>Location (e.g., G-13, Islamabad).</li><li>Time Constraint (e.g., Tomorrow Morning).</li></ul></li></ul><h3><a id="_c1gj4j3wlhj"></a><strong>Step 3: Real-World Discovery</strong></h3><ul><li><strong>Action:</strong> The Antigravity agent autonomously formats a query and hits the Google Maps Places API.</li><li><strong>Query:</strong> find nearby "AC repair" near "G-13, Islamabad"</li><li><strong>Return:</strong> The API returns a JSON list of real, local businesses with their coordinates, distances, and aggregate ratings.</li></ul><h3><a id="_99abpjt46cku"></a><strong>Step 4: Logic &amp; Ranking</strong></h3><ul><li><strong>Action:</strong> The agent analyzes the real-world data and injects "mock" availability parameters.</li><li><strong>Process:</strong> It ranks the top 3 providers based on distance + rating. It then applies a logical rule to select the absolute best option and formulates a human-readable reasoning string.</li></ul><h3><a id="_vdba9oz5up6j"></a><strong>Step 5: The Simulation Execution (Critical Requirement)</strong></h3><ul><li><strong>Action:</strong> The agent executes the booking.</li><li><strong>Process:</strong> (Detailed comprehensively in Section 4 below).</li></ul><h3><a id="_ukwiyzavq5m0"></a><strong>Step 6: Follow-up &amp; UI Update</strong></h3><ul><li><strong>Action:</strong> The user is notified, and a follow-up is scheduled.</li><li><strong>UI Component:</strong> The Flutter UI updates to show an active booking card, and 10 seconds later, a simulated "Reminder" push notification fires.</li></ul><h2><a id="_uiry81a8nu2k"></a><strong>4. How the Action Simulation Actually Works (No Loopholes)</strong></h2><p>The hackathon strictly requires simulating booking, scheduling, and provider assignment without building a massive two-sided marketplace . Here is exactly how the technical handshake works between Flutter, Antigravity, and Firebase to achieve this.</p><h3><a id="_bkam9e89f85g"></a><strong>The Firebase Structure</strong></h3><p>Set up a simple Firestore database with a collection called active_bookings.</p><h3><a id="_ims6flpifk7k"></a><strong>The Handshake Protocol</strong></h3><ol><li><strong>The Agent Decides:</strong> Antigravity selects "Ali AC Services" from the Google Maps data.</li><li><strong>The Agent Writes:</strong> Antigravity executes an HTTP POST request to Firebase. It creates a new document in active_bookings with the payload:</li><li>JSON</li></ol><p>{</p><p>  "user_id": "123",</p><p>  "status": "confirmed",</p><p>  "provider_name": "Ali AC Services",</p><p>  "service_time": "10:00 AM",</p><p>  "provider_distance": "2.1 km",</p><p>  "reasoning": "Closest available provider with a 4.8 rating."</p><p>}</p><ol><li><strong>The Flutter App Listens:</strong> set up a StreamBuilder in Flutter that constantly listens to the active_bookings collection for this specific user.</li><li><strong>The UI Reacts:</strong> The moment Antigravity writes that JSON to Firebase, the Flutter app instantly detects the change. The UI transitions from a "Searching..." loading spinner to a beautiful "Booking Confirmed!" receipt card.</li></ol><p><strong>Why this wins points:</strong> It perfectly simulates a backend system state change. It proves end-to-end execution without needing a seller to physically tap "Accept" on a separate app.</p><h2><a id="_7q9bwbtla5hj"></a><strong>5. Google Antigravity Agentic Workflow Design</strong></h2><p>To score maximum points in the "Use of Google Antigravity (25%)" criteria , you must set up the agent with traceable, multi-step reasoning.</p><h3><a id="_tl7rlahfkgu6"></a><strong>Agent Setup</strong></h3><p>Create a primary Orchestrator Agent equipped with specific tools:</p><ul><li><strong>Tool 1: parse_intent</strong> (Extracts variables from Roman Urdu).</li><li><strong>Tool 2: fetch_google_maps_data</strong> (Executes the API call based on parsed variables).</li><li><strong>Tool 3: rank_and_select</strong> (Applies the logic to pick the best provider).</li><li><strong>Tool 4: execute_firebase_booking</strong> (Fires the JSON payload to simulate the system change).</li></ul><h3><a id="_w3ot7qb77kw"></a><strong>Traceable Decision Making</strong></h3><p>Ensure the agent logs its thought process at every step. Ranking by rating.</li><li>Log: Selected Ali AC Services (Rating: 4.8, Distance: 2.1km).</li><li>Log: Triggering booking simulation to Firebase...
